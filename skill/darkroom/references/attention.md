# Attention and word budgets

## The evidence

- Users read about **20 %** of the words on an average web page; at most ~28 % (Nielsen 2008, from Weinreich et al., ACM TWeb 2008; 25 participants, highly literate — real audiences read less).
- Each extra 100 words buys ~4.4 s more on page. Pages ≤ ~110 words get roughly half read.
- Efficient readers scan in a **layer-cake** pattern (headings → the body they need). Walls of text produce the F-pattern: first lines and left edge only (NN/g eyetracking).

## Budgets (defaults; the bible may change them)

| Element | Budget |
|---|---|
| Headline | ≤ 8 words, ≤ 2 lines at desktop display size |
| Hero body | ≤ 30 words |
| Feature / chapter body | ≤ 45 words |
| Proof / detail section | ≤ 60 words, or a list of ≤ 5 short items |
| Closing / CTA section | ≤ 30 words |
| Landing page total | ~400–900 words; > 1,200 is a brochure |
| Labels / microcopy | 1–4 words |

Long-form pages (articles, menus, docs, catalog detail) are *Read* surfaces: budgets don't apply, structure does (headings every 2–4 paragraphs, 45–75ch measure).

## Cadence: something to look at every few seconds

A scroller moves roughly one viewport every 3–6 seconds. Each viewport needs a **hook** — not necessarily something new, but a change:

- scale (object grows, type jumps size), light (sweep, grade change), reveal (mask, unfold), image change, colour-field change, a single motion that explains the claim.

Repetition kills cadence: the same block (feature strip, icon row, card grid) in 3+ sections reads as filler. Two consecutive sections of the same layout family is a flag.

## How to cut copy

1. Write the section claim in one sentence. Delete everything that doesn't support it.
2. Replace adjectives with one concrete fact or image.
3. Move secondary detail to a page the motivated reader can open (specs, FAQ, menu PDF *download* after an HTML menu).
4. Kill the genre verbs (unlock, elevate, seamless, supercharge, revolutionize…).
