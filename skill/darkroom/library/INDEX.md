# Example library — index

Written lessons from real websites (and some mockups) judged **good** or **bad**. No screenshots ship with the skill; each entry is ≤ 60 lines of observations, measured signals and transferable rules. Maintained with `/darkroom learn`; do not edit by hand except to fix errors.

## How commands use it

Load this index, then **only** the entries that match the project, at most **4 good + 2 bad** per command run. Match in this order: (1) the **technique** the project needs, from its motion level and storyboard (a `story` or `hero-effect` page looks up its scroll technique in **By technique** below first); (2) same `category`; (3) same `packs`. When a technique row names a recipe, build the effect from that recipe, not from scratch. Prefer `confidence: high`. Always load `LESSONS.md` (cross-site rules). Cite entries by slug when they justify a decision ("as in `good/<slug>`"). Entries are evidence, not templates: never reproduce a listed site's layout, imagery or copy.

## By technique

Look here first when the project's motion level is `hero-effect` or `story`, or the user names an effect ("like ScrollTide", "scroll animation with frames", "parallax"). Each row lists the entries that do it well, what to build it with, and the one thing that most often goes wrong. The 2026-10-27 batch, the 2026-10-29 AI-era motion batch and a few older entries carry `techniques:` tags; untagged entries can still match by category.

|---|---|---|---|---|
| `frame-scrub` | a rendered camera move (product flight, assembly, dive) played frame by frame by scroll | seasats, lunarwheel (as frames, not live 3D), royal-pop (35 MB of frames: heavy) | `recipes/scrub-frames.js` + `darkroom media frames --format avif --mobile-width 900` | a phone frame set and coarse-to-fine loading; live claims in HTML over the canvas |
